# Super Drive OS — final audit and production readiness (2026-11-08)

Scope: Nino's final QA brief. Business logic was **not** changed. Everything below was measured on this machine on a **copy** of the local database (never the real data, never Neon, nothing pushed or deployed). "Tested" means it was actually run; what could not be tested is listed in section 9.

## 1. Application health
**Overall: sound.** No broken page, no crash, no console error, no failed request and no horizontal overflow in the page sweep; every sensitive action is checked on the server.

Found and fixed:

| # | Finding | Fix |
|---|---|---|
| 1 | **The camera was blocked.** `next.config.ts` sent `Permissions-Policy: camera=()`, which makes every browser refuse the camera, so the warehouse QR scanner could never open it on a phone (the screen would have said "allow the camera in settings", which cannot help). | `camera=(self)`. Checked in the production server's response headers. |
| 2 | Staff signed in with a username; no account had an email. | Email sign-in (section 6). |
| 3 | Neon readiness: migrations had no unpooled address, no connection timeouts, `.env.example` and `docs/DEPLOYMENT.md` were out of date. | `DIRECT_URL` used by migrations and the seed; 15 s connect and 30 s idle timeouts; docs rewritten. |
| 4 | 81 foreign keys without an index. | 30 additive indexes on columns that are searched or joined (migration `foreign_key_indexes`). The other 50 are "who did it" columns that are rarely queried; left alone on purpose. |
| 5 | The first index set included one **redundant** index (`StockBalance.productId`, already the start of the primary key). With it, the concurrency test "opposite transfers do not deadlock" failed about 2 runs in 10; without it 0 in 22 runs, then two full runs of 215/215. | Dropped (migration `drop_redundant_stock_balance_index`). **Rule: never add an index to a table the stock engine locks without running `npm run test:db` several times.** |
| 6 | Tiny 9 px labels in the Director banner. | Removed (the banner numbers show from `lg` only, at 11 px). |
| 7 | A wrong password cleared the email box. | The typed email stays. |
| 8 | `.next-*` build folders were not git-ignored. | Added. |

What remains (none of it blocks the first deploy): section 9.

## 5. QR code testing
- **Generation:** `qrSvg` draws the code on the server from `SDOPU:<24 random bytes>`; two notes never share a code (tested).
- **Readability:** the generated SVG is drawn into a grey picture and decoded with the same zxing reader the scanner page bundles; the text comes back exactly (tested, `src/lib/qr.test.ts`).
- **Verification:** the code carries only a token. `scanAction` needs the `warehouse.operate` permission, looks the note up in the database by token, ignores everything else in the text (a code with prices or names is only used as a token and finds nothing), logs rejected scans, and refuses cancelled, finished or unauthorised notes. Releasing twice is impossible (database tests: release, partial release, double submit, cancelled note, immutability).
- **Printing and download:** the A5 note prints and saves as PDF (tested earlier with Chrome).
- **Camera:** the scanner page uses the browser camera with clear messages (no camera, blocked, in use, not https) and a typed-code fallback. **It could not be tested with a real camera here.** The blocker found in this audit (the camera header) is fixed; one scan on a real phone over https is still needed.

## 6. Authentication
- Staff sign in with **email + password** (Show / Hide password button; the typed email stays after a mistake; emails are case-insensitive).
- The database now requires every account to have a unique, lowercase email (NOT NULL + CHECK). The old `username` column stays as an internal handle (made from the email). There is no public registration.
- The Director creates employees (Roles → Add member: full name, **email**, role, temporary password; they must change it at first sign-in), changes role, deactivates and resets passwords. A Director can only be created or changed by a Director; nobody can change their own role or status; the last active Director cannot be removed. This was already enforced on the server and is unchanged.
- Passwords: bcrypt cost 12, 8-72 characters with a letter and a number. Sessions are random tokens stored hashed (12 h, httpOnly, SameSite=Lax, Secure in production). 5 wrong passwords lock the account for 15 minutes. A deactivated account loses access at once. Unknown emails are logged in the audit.
- **Forgot password:** there is no email sender in this system, so "forgot password" means "ask the Director to reset it" (the sign-in page says so). Self-service reset by email needs an email service and was not built.
- Existing local accounts received placeholder emails (`owner@superdrive.local`, ...) by Nino's choice; he replaces them in Roles / My profile. An empty production database is unaffected: the first Director comes from `ADMIN_EMAIL` + `ADMIN_PASSWORD`.

## 7. Database (Neon + Prisma)
- Prisma 7 with the pg adapter. The app uses `DATABASE_URL` (Neon pooled address). Migrations and seed use `DIRECT_URL` when it is set, else `DATABASE_URL`. Nothing is hard-coded; secrets live only in `.env` / Vercel.
- 8 migrations from today are pending for production (listed in `docs/DEPLOYMENT.md`); all apply cleanly to a fresh database (the test database is built from zero by them on every `test:db` run). None deletes data; the email migration only adds emails and constraints.
- Not tested: a real connection to Neon.

## 8. Deployment (Vercel)
- `next build` compiles and type-checks (103 routes); `next start` on that build served every test above.
- `vercel.json` has the four cron jobs; each checks `CRON_SECRET` with a constant-time compare.
- Security headers: frame denied, no sniffing, strict referrer, camera only for the site itself. No Content-Security-Policy (section 9).
- **Not deployed and not tested on Vercel.** Nothing was pushed (standing rule). A live smoke test is listed in `docs/DEPLOYMENT.md` section 6.

## 9. Outstanding issues
1. Scan with a real camera on a phone over https (cannot be tested here).
2. First deploy: connect Neon, run the migrations and the seed, then the live smoke test; put the Vercel region next to the Neon region.
3. Replace the `@superdrive.local` placeholder emails with real ones.
4. Forgot-password by email is not built (no email service); the Director resets passwords.
5. WhatsApp (CallMeBot and the Cloud API) has only ever been tested with a fake sender.
6. No Content-Security-Policy and no per-address login throttling (the per-account lock exists). Both are worth adding after launch; a strict CSP needs care with Next's inline scripts.
7. A page that is "not found" inside the app answers HTTP 200 (the page streams). The content is a proper not-found screen and exposes nothing.
8. The test run prints a pg warning ("client.query() while already executing a query, removed in pg 9"). Harmless today; check it when upgrading `pg`.
9. About 30 labels use 10 px type (small uppercase captions and badges). Readable, but not generous.
10. Speed was measured on a small local database (server time under 135 ms per page, 90-290 KB of HTML before compression). Real speed depends on the Neon round trip; not measured.

## 10. Final recommendation
**READY AFTER MINOR FIXES.** The code, the data rules, permissions and layout held up under every automated and browser check, and the one real blocker found (the camera header) is fixed. It is not yet "ready for production" because the live pieces were never exercised: a real Neon connection, a Vercel deploy and a camera scan on a phone. Do items 1-3 above on the first deploy, then it is ready.
